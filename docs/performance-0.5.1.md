# Zex 0.5.1 性能与显示适配验证

验证日期：2026-10-30。环境为 Windows 11 x64、Qt 6.8.3、3840×2160 单显示器，系统缩放 200%。以下是本机重复运行、磁盘缓存已预热后的数据，不能等同于其他机器的冷启动速度。

## 本次修复

- 恢复的窗口按屏幕可用区域缩小并定位；屏幕、工作区或 DPI 改变后重新检查，保留最大化状态。显示器按各自矩形处理，支持负坐标和屏幕之间的空隙。
- 外观和 Windows 集成设置改为可滚动内容，操作按钮固定在底部；欢迎页在较矮窗口中也可以滚动。
- 搜索计数和前后导航改为分批扫描，通常每块 512 KiB，每轮约 8 ms 后交还事件循环。块间保留重叠，避免漏掉跨边界的 UTF-8、大小写折叠和全字匹配。更改关键词、清空搜索、重载文件或销毁编辑器会取消相应任务。

## 测量结果

`startup_to_ready_ms` 从原生启动器入口计时，到文件就绪且窗口可见；不包含进入入口前的 Windows 进程创建耗时。界面响应间隔由 16 ms 定时器测量，表示观察到的事件循环间隔，不是搜索完成耗时或帧率保证。

| 场景 | 窗口可见 | 文件就绪 | 文件就绪后最大界面间隔 |
| --- | ---: | ---: | ---: |
| 10 MiB 日志，搜索不存在的文本 | 391 ms | 453 ms | 26 ms |
| 100 MiB 日志，搜索不存在的文本 | 391 ms | 1000 ms | 25 ms |
| 240 MiB 日志，搜索不存在的文本 | 422 ms | 1860 ms | 26 ms |
| 1 MiB 单行，搜索行末文本 | 422 ms | 1110 ms | 18 ms |

相同搜索测试在修改搜索实现前，100 MiB 和 240 MiB 文件就绪后的最大界面间隔分别为 370 ms 和 847 ms。本次验证分别降到 25 ms 和 26 ms。

小文件单标签启动三次为 390 / 406 / 422 ms，中位数 406 ms；恢复 100 个标签为 484 / 485 / 485 ms，中位数 485 ms。100 个标签每次都只载入当前文件，另外 99 个保留为未加载占位标签，并核对顺序与活动标签。背景文件故意不存在，用来确认启动阶段不会尝试读取它们。

257 MiB 文件被正常拒绝，显示错误且没有崩溃；当前上限仍为 256 MiB。

## 显示与功能检查

- 通过进程级 `QT_SCALE_FACTOR` 验证有效缩放 100%、125%、150%、200%、300%、400%；未修改系统显示设置。所有主窗口和两个设置窗口的完整外框均位于可用区域内。400% 时逻辑可用区域为 960×516。
- 自动测试覆盖模拟负坐标副屏、显示器移除、不同尺寸工作区、屏幕间空隙，并通过真实窗口事件验证重新定位及最大化/还原。
- 32 项 Qt 测试通过，包括跨块中文/大小写折叠/全字匹配、双向循环查找、超出 10,000 条高亮上限后的导航、搜索取消，以及既有会话、编码、主题和 Windows 集成回归。
- 性能脚本共 18 个独立进程场景；发布包另由 `verify-package.ps1` 在中文目录、系统 PATH、不同工作目录中检查主题、搜索、编码恢复和原生单实例。注册表测试使用隔离测试项。

## 限制与复现

只有一台实体显示器，尚未验证真实混合 DPI 多屏拖动和热插拔，也未在 Windows 10 实机复测。多屏结论仅涵盖布局算法及模拟事件测试。

超长单行仍由 Scintilla 整行布局：1 MiB 单行的首次载入期间，本次测得约 671 ms 的最大界面间隔。分批搜索改善的是文件就绪后的响应，不代表首次大文件插入、单行布局或自动换行已完全异步。

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
python scripts/verify-performance.py --label release-0.5.1 --enforce
powershell -ExecutionPolicy Bypass -File scripts/verify-package.ps1
```

性能报告和截图位于本地 `artifacts/performance/release-0.5.1/`，该目录不提交到仓库。测试不会改写日常会话或打开的源文件；显式指定的测试会话会在测试目录中保存。
